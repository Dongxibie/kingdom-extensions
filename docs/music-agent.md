# 音乐 Agent / Music Agent

> 把一首曲子（MIDI 文件或简谱文本）翻译成「按哪些键、什么时候按」，并让它能在网页里回放出来。

## 这个模块解决什么问题

很多人玩虚拟乐器（手机游戏里的两排键盘、八音盒、口风琴）时都会遇到同一件事：
心里知道想弹哪首曲子，但不知道曲谱上的音对应哪个键、超出音域的音该怎么办。
这个模块把这件事自动化：解析曲子 → 映射到具体乐器的键位 → 给出可照着练的按键序列 → 在网页里演示一遍。

## 第一版范围（刻意划定的边界）

| 做 | 不做 |
| --- | --- |
| MIDI 文件解析（JDK 自带 `javax.sound.midi`，纯 Java） | MP3 / 音频分析（需要别的技术栈） |
| 简谱文本输入（1-7、休止、八度、变化音、时值记号） | 曲谱识别（拍照/扫描成谱） |
| 音符时间线（钢琴卷帘 + 按键轨） | 多轨混音编辑 |
| 乐器按键档案映射与按键序列导出 | 真实系统按键输入（见桌面代理协议） |
| 网页内 Demo 回放（WebAudio 合成 + 键盘高亮） | 高质量音源 |

## MIDI 解析里三个容易做错的地方

1. **tick → 毫秒**：MIDI 的时间单位是 tick，换算依赖每拍分辨率（PPQ）与 tempo，而 tempo 可以中途改变。
   实现先把文件里所有 tempo 变更收集成一张表，再分段累加换算；如果只用开头的 tempo 平推，变速段落之后的时间轴会整体偏掉。
2. **力度为 0 的 Note On 等于 Note Off**：很多导出工具用「力度 0 的按下」表示松开。
   只认 `NOTE_OFF` 会漏掉一半音符，结果是整首歌都没有时长。
3. **同音重叠**：同一音高连续按下两次时，松开事件是按后进先出配对的。
   用栈（`Deque`）而不是单个变量记录，时长才不会串成一条。

这些都有单元测试：测试自己用 `javax.sound.midi` 造序列、算出期望值，不依赖外部 `.mid` 样本文件（样本丢了测试也不会跟着烂掉）。

## 简谱解析支持的写法

```
1=C 4/4 BPM=96
1 1 5 5 | 6 6 5 - | 4 4 3 3 | 2 2 1 -
```

| 写法 | 含义 |
| --- | --- |
| `1` – `7` | 音级（`1=C` 时 1 就是 C） |
| `0` | 休止，不发声但占用时间 |
| `'` / `,` | 每多一个升高 / 降低八度（`1'` = 高八度，`1,` = 低八度） |
| `#` / `b` | 升 / 降半音 |
| `-` | 延长一拍（`5 -` 是两拍） |
| `.` | 附点（时值 ×1.5） |
| `_` | 减时线（时值减半，可叠加） |
| `|` | 小节线，只断句不发声 |

两处刻意的设计：调号（`1=C`）会被真正换算，因为「简谱的 1 唱哪个音」全靠它决定，忽略它会导致整首曲子移调；
每行谱面会补齐到小节末，所以在文档里分行写的谱子读起来和纸面对得上。

## 映射引擎：最核心的一段

**键与音的对应不是等差数列。** 只有白键的乐器上 C 后面直接是 D（没有 C#），而键盘式排列相邻键差半音。
同一个音高在两套乐器上落在第几个键，答案完全不同。所以引擎按三种方式**先展开一张键位表**，再拿音符去查：

| 映射方式 | 键位怎么排 | 例子 |
| --- | --- | --- |
| 半音排列 `CHROMATIC` | 相邻键差 1 个半音 | 键盘式 12 键：Z=C4, S=C#4, X=D4 … |
| 音阶排列 `DIATONIC` | 相邻键差 1 个音级 | 光遇式 15 键：Z=C4, X=D4, C=E4 … |
| 自定义 `CUSTOM` | 同半音排列，键位由档案定义 | 八音盒 8 键：A=C4 … K=C5 |

超出音域时按档案策略处理，**每一种都会在导出文本里写明理由**，不会悄悄丢音符：

| 策略 | 行为 |
| --- | --- |
| `SKIP` | 跳过，并记进「未能落键」清单（含音名、时间、原因，以及本档案的音域） |
| `NEAREST` | 就近落到最接近的键上，标记为「已调整」，音名写成 `C#4→C4`；距离相同时取更低的键 |
| `SHIFT_OCTAVE` | 整段挪八度；挪回音域内如果那个音不在这套键上（音阶排列常见），再按就近处理 |

同时按下的多个音会归成一组（和弦），导出时写在同一行；移调（半音）与升降八度会一起作用到落键上。

### 交叉验证

同一首小星星走两条入口，结果一致：

| 入口 | 音数 | 速度 | 时长 | 音域 |
| --- | --- | --- | --- | --- |
| `demo/twinkle.mid`（MIDI 解析） | 14 | 96 BPM | 10000ms | C4–A4 |
| 简谱文本（`1=C 4/4 BPM=96` 那四小节） | 14 | 96 BPM | 10000ms | C4–A4 |

同一首 C 大调音阶在三套内置档案上的结果：

| 档案 | 键数 | 结果 |
| --- | --- | --- |
| 光遇式 15 键 | 15 | 8 个音全部落键、0 调整 |
| 键盘式 12 键 | 12 | 7 个落键，C5 未落键（高于上限 B4，策略为跳过） |
| 八音盒 8 键 | 8 | 8 个音全部落键（超范围的音按策略移八度） |

## 时间线与回放

- **钢琴卷帘**：横轴是时间、纵轴是音高（按全曲最低音偏移计算）、块宽是时值；变化音与自然音分色。
- **按键轨**：每一次按键动作单独标记，和弦显示成 `Z+C`，被调整过的组用虚线框标出。
- **定位**：在卷帘或按键轨上点击/拖动即可跳到任意位置；播放中定位会从新位置继续。
- **Demo 回放**：网页内用 WebAudio 合成发声（三角波 + 快速起音、指数衰减包络）。
  发声用的是**按键实际对应的音高**，所以听到的就是这套乐器照着按键弹出来的效果，包括被就近或移八度调整过的音。
  调度走 `AudioContext` 的时钟而不是 `setTimeout` 累加——后者在标签页切换、主线程忙时会累积漂移，几十个音符之后整条旋律就跑偏了。
  停止时关闭音频上下文，保证不会在按了停止之后还继续响。

**这条链路不会驱动任何系统输入。** 真实按键执行是另一个模块（桌面代理）的事，且只到协议为止。

## 曲库、分析、优化与演奏方案（产品化增强）

把「上传 → 解析 → 映射 → 导出」这条链路做成一个能长期用的工具，缺的从来不是底层能力，而是四件小事：
**找得到、看得懂、改得动、演得出**。

### 曲库：收藏、搜索、难度、创建时间

曲目卡片上直接摊开一首曲子的全部事实：名称 / 来源 / 类型（MIDI 或简谱）/ BPM / 音符数 / 音域 / 难度 / 创建时间。
收藏是一个开关，可以只看收藏；搜索按曲名与来源匹配。

**难度星级只用库里已有的四个字段**（音符数、时长、速度、音域跨度）算：
跨度与速度各能贡献 0-2 分、密度 0-2 分，满分 6 分，按一张明确的对照表折算 1-5 星。
这么做是因为曲库列表和详情卡都要显示难度，而列表页不该为了一个星级把音符全查出来 ——
同一个方法两处共用，所以两处的星级永远一致。和弦比例不参与星级（它是「演奏方式」的复杂度），
在分析卡里单独说明。

### 分析卡：推荐键位是试出来的，不是猜出来的

解析完一首曲子，使用者想立刻知道五件事：难不难、多快、音域多宽、要弹多久、该用哪套键位。
前四个直接从库里算，第五个**把每个乐器档案都真实跑一遍映射**：谁能把所有音落下、谁用的键最少就推谁。
所以推荐结果与你自己在编排台里逐个试出来的结论一致，另外还给出两张备选方案与它们的落键情况。

### 优化器：说清「在哪、为什么、怎么办」

五条检查，每条都有明确的后果：

| 检查 | 后果 | 建议（可直接应用） |
| --- | --- | --- |
| 同键重按太密 | 在某些输入路径上会被当成重复而丢掉 | 把同一个键「松开到再按下」的空档留到 60ms 以上 |
| 超出音域 | 有音根本没落键 | 自动移八度，或换成音域更宽的档案 |
| 多键和弦 | 小乐器按不出来 | 换键数更多的档案 |
| 按键过密 | 手速跟不上 | 降速到某个倍率 |
| 长按音 | 部分乐器不支持长按 | 提示（无需改动） |

判定的口径统一是「上一次**松开**到这一次**按下**之间的空档」—— 含「还没松开就又按」这种 0 空档。
建议不是写给人看的文案，而是方案里能直接改的参数：点一下「应用建议」，方案就更新了。

### 演奏方案：同一首曲子可以有好几套打法

演示要原版、教学要简单版（键少、都能落下）、短视频要快速版（节奏更紧）。
方案把四个旋钮存成一条记录 —— **用哪个乐器档案、超范围怎么处理、速度倍率、同键最小间隔**。

内置三套不是写死的常量，而是按库里现有的乐器档案现算的：原版用默认档、简单版用键数最少的那档（并自动移八度）、
快速版在原速上 ×1.35。换一批档案，内置方案跟着变。方案也存在库里（`music_performance_preset`），
可以另存自己的设置、改名、删除。

**速度与间隔都在「序列」这一层生效**，之后仍然走原来那条校验（最短按住 40ms、命令数上限、单键校验都不绕开）；
不指定方案时行为与以前完全一致。

### 演示模式与导出中心

演示模式只有两步：选一首曲子 → 点开始。之后全屏铺开大号当前时间 / 当前音符 / 当前按键、
键盘实时点亮、时间线走针、音频播放、接下来几组按键预告，可循环。面向的是「拿给别人看」这一场景。

导出中心顶部直接给「多少事件、几秒、几组按键、用了几个键」，下面一行是三种格式的支持情况与体积，
保留逐格式预览与复制。切换方案时事件数不变、时长跟着变（例如 20.0 秒 → 14.8 秒）。

## 数据模型

```
music_task ──1:N── music_note
     │
     └─ name, source_type(MIDI/JIANPU), source_ref, note_count, tempo_bpm,
        time_signature, duration_ms, pitch_low, pitch_high, status

instrument_profile（独立表，不写死乐器）
     └─ name, game, instrument, octave_range, special_rules,
        mapping_mode, scale, key_layout(JSON), base_pitch,
        transpose, octave_shift, unmapped_strategy, status

performance_share（曲谱分享，快照自包含）
     └─ share_code(唯一), performance_plan_id, task_id, creator, title,
        difficulty, game, instrument, note_count, duration_ms, import_count,
        payload(曲名/来源/速度/拍号/难度/方案/演出计划/音符表), deleted
```

时间统一存毫秒，不存 MIDI 的 tick —— tick 的含义依赖 tempo 与每拍分辨率，换首曲子就不能直接比较了。
新增一种乐器只需要往 `instrument_profile` 插一条数据（按键顺序 JSON + 基准音高 + 音阶 + 超范围策略），不需要改代码。

## 演奏宏导出（Performance Macro Export）

解析与映射之后还有一层：把「按键序列」变成**可以带走的脚本**。三种格式都从同一份「演奏计划」生成，所以同一首曲子每次导出的节奏完全一致。

| 格式 | 给谁用 | 特点 |
| --- | --- | --- |
| TXT 按键时间线 | 人 | `0.63s 松开 Z` 这样逐行列出，照着练或打印 |
| AutoHotkey v1.1 脚本 | 机器 | 按下 / 释放 / 按住时长 / 事件间隔齐全；F9 开始、F8 暂停、ESC 急停并松开所有键 |
| JSON 演奏计划 | 程序 | `notes` 是事件流（`{key, action, timestamp}`），可直接喂给执行通道或别的工具 |

**时序只有一处定义**：事件流来自桌面代理那层已经校验过的命令流（最短 / 最长按住截断、同键未松开不得再按、单键校验），
导出脚本的节奏与派发计划必然一致；被顺延或截断的地方逐条写进 `warnings`，既不隐藏也不假装精确。

**执行层的边界**：抽象成 `ExecutionAdapter` 之后，模式只有三种，且默认最保守 ——
`PREVIEW` 只列出将要发出的命令（不产生任何真实输入），`MANUAL` 与 `LOCAL` 如实说明「未开启」以及开启前必须先具备的三条
（随时可用的急停、只对前台窗口生效、显式开启开关）。这样界面上的「执行」永远有确定行为：要么给你可核对的命令流，要么明确告诉你缺什么。

## 本机演奏运行时（Local Performance Runtime）

导出的脚本之外，还有一个**在应用内直接演奏**的通道。它是有状态的会话，不是一次性脚本：

| 闸门 | 做法 |
| --- | --- |
| 默认关闭 | 配置开关 `kingdom.music.local-execution.enabled`，不打开时「开始」按钮不可用 |
| 显式确认 | 开始接口要求 `confirm=true`，并提供目标窗口；缺任一项直接拒绝 |
| 窗口限定 | 执行前自检显示当前前台窗口并要求确认；演奏中窗口一换就**自动暂停** |
| 守护进程 | 只读脚本 `tools/ks-performance-guard.ps1`：只查 ESC 一个键 + 只读前台窗口标题 |

安全行为：ESC 随时急停（与手动停止走同一条路径，立刻松开所有按下的键）、暂停也立刻松键、
异常退出在 finally 里释放、一次只允许一个会话、只发按键（不动鼠标、不注入进程、不后台隐藏执行）。
执行监视器实时显示状态 / 进度 / 当前按键 / 剩余时间 / 按住的键。

## AI 音乐助手（Performance Strategy）

三种演奏策略，AI 负责理解、规则负责改写：

| 策略 | 改什么 | 不改什么 |
| --- | --- | --- |
| 初学 Beginner | 精简同时按下的音与过短经过音、收窄跨度、降速（80%，不低于 72 BPM） | 音名与旋律顺序 |
| 标准 Normal | 不改 | 全部 |
| 展示 Showcase | 重拍加力 25%、长音时值 +8% | **音高序列与音符数量一个不动** |

模型（OpenAI 兼容，`MUSIC_LLM_*`）只输出 `{difficulty, instrument, suggestion[]}`：
难度档必须落在白名单里，认不出来就丢弃并回退规则判断；建议条数与长度都截断。
每条改动都带「改了什么 + 为什么」，直接作为解释展示；点「应用方案」生成一条新曲目（原曲不动，重复应用幂等）。

## 难度分层、游戏乐器生态与曲谱分享（V1.2）

### 难度：星级之上给出分层与适合谁

三轴计分（音域跨度 / 速度 / 密度）算出 1–5 星，再归纳成三档分层并说明适合谁：

| 星级 | 文字 | 分层 | 适合谁 |
| --- | --- | --- | --- |
| ★ | 入门 | 简单 | 新手 |
| ★★ | 简单 | 简单 | 新手 |
| ★★★ | 进阶 | 普通 | 有基础 |
| ★★★★ | 较难 | 普通 | 有基础 |

### 游戏乐器生态：匹配是试出来的

乐器档案新增**游戏、可用音域、注意事项**三个字段，于是「游戏 + 乐器 + 键数」就能作为一次查询条件：

| 打分项 | 权重 | 说明 |
| --- | --- | --- |
| 全部落键 | +100 | 真实跑一遍映射，所有音都落得下来 |
| 未落键 | 每个 −5 | 有音落不下来就扣分 |
| 键数距离 | 每差 1 键 −1 | 越接近目标键数越靠前 |
| 游戏命中 | +40 | 档案所属游戏与目标一致 |
| 乐器命中 | +25 | 乐器名与目标一致 |

每个候选都带理由文案，例如「所有音都能落键，不需要改动曲谱」「键数正好是你要的 15 键」
「键数与目标差 10 个（实际 25 键）」。内置档案已经带上游戏信息（光遇式 15 键 / 键盘式 12 键 /
八音盒 8 键 / Minecraft 音符盒 25 键），也可以在界面上直接新建、编辑、删除。

### 曲谱分享：演奏码 + 自包含快照

演奏码形如 `KS-MUSIC-2026-A001`：年份 + 字母段 + 三位流水，单字母段满 999 进位到下一段。
快照里带曲名、来源、BPM、拍号、难度、方案（键位 + 策略 + 速度 + 间隔）、演出计划与完整音符表，
导入方不需要有原作者的数据库，就能在本库还原成一条**来源标注为「分享」**的新曲目，
导入后可以直接演奏或导出脚本，被导入次数同步 +1。

新增接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/music/tasks/{taskId}/profiles/match` | 游戏乐器匹配（game / instrument / keyCount / limit） |
| POST | `/api/music/shares?taskId=` | 生成演奏码 |
| GET | `/api/music/shares` | 分享列表 |
| GET | `/api/music/shares/{shareCode}` | 按码查看摘要 |
| POST | `/api/music/shares/{shareCode}/import` | 导入还原成新曲目 |

### 工作台界面：黑色 + 深灰 + 紫绿

界面从「后台管理页」改成三栏演奏工作台：左 = 音乐库（我的歌曲 / 最近演奏 / 收藏 / 分享）与游戏乐器选择，
中 = 时间线与虚拟键盘，右 = AI 助手与演奏优化。底色 `#07080b` 起、面板 `#0f1115` 一级层叠，
强调色只有紫 `#a78bfa` 与绿 `#6ede9a` 两支，音符块用绿、按键高亮用紫。
最近演奏记在本地，换曲子时方案会跟着换成这首曲子自己的方案。

### 自动演奏准备层：只完善接口

`execute / pause / stop / status` 四个动作对应到已有执行层（演出计划 → 执行适配器 → 会话），
不新增抽象：开始需要用户主动点击并勾选确认、目标窗口在前台；窗口一换自动暂停；ESC 随时急停。
预览执行器只做模拟（时间线走、键盘亮、状态回报），不向系统发送任何按键；
模块默认关闭，需要后端显式开关，不存在后台隐藏执行，也不注入任何进程。
